---

这是整个工作流的核心入口：**列模式 → 用户选 → 补上下文 → 衔接起步节点**。

1. **列模式**：跑 `python3 .workflow/engine/cli.py list-profiles`，输出原样贴给用户。内部可能顺手自动升级，相关输出不要疑惑；若提示「请重新运行 /workflow-start」，再跑一次。
2. **顺手推荐（可选、不强制）**：各 profile 的 desc 已带适用信号，看用户需求有明确信号就顺手补一句推荐，看不出就默认软推研发档。**绝不为了凑推荐去问用户任何问题。**
3. **补上下文邀请（选完模式、进 start_node 之前）**：用户回了编号、正要进澄清节点的这一刻，**读 `context-invite.md`** 把「补背景」邀请发给用户，然后把话头交回用户——这是敞开一扇门，不是设一道关。很多用户丢完 PRD 就本能想开干，这一步只是给愿意补背景的人一个开口的机会；想说就接住，不想说就直接进 start_node，别催、别追。
4. **衔接起步节点**：注意用户补完上下文，不要现场查看内容，内容是给后续的`start_node`准备的，立刻读该 profile 的 `start_node` 直接调起（如 `/workflow-explore`）。
5. **记录当前选定的 profile**：start_node 之后的 `/workflow-engine init` 必须显式带 `--profile <名>`，靠这里的记录传递。
