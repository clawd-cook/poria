# workflow-pit-record：学习层写手（踩坑 + 经验）

把一条**规定性**学习写进对应 `docs/spec-rule/<阶段>-rule.md`：

- `pit`（踩坑，犯了错/会踩的坑）→「踩坑」段，**频次/严重度驱动**升级。
- `exp`（经验，这阶段怎么做更好）→「经验」段，**信心驱动**升级。

归因主判在上游——调用方（feedback-loop / 手动 capture / archive）判好「写哪份文件、根因哪阶段」再来调本 skill；手动 capture 缺字段时本 skill 交互补齐（见「入参」）。

> 学习层豁免 CLAUDE.md「任务中不直接写 docs/」——那条管任务产物（TRD/schema），学习层一直内联写。

## 入参

```
/workflow-pit-record --kind pit --file <spec-rule 路径> --title "..." \
            --lesson "<教训，脱离场景也成立>" --scene "<触发场景>" --fix "<修正>" \
            --root <workflow-explore|workflow-implement|workflow-test-plan|workflow-test-cases> \
            --intercept <实际发现它的来源节点> --severity <high|normal> --source "<出处>"

/workflow-pit-record --kind exp --file <spec-rule 路径> --title "..." \
            --insight "<怎么做更好>" --applies "<适用场景>" --source "<出处>"
```

`--kind` 缺省 `pit`。手动 capture（「记一下」）直调本 skill，缺 `--root`/`--intercept` 时交互补齐——拦截 = 当前窗口所处节点，根因 AI 推断 + 人一句确认。还没修的问题不归这里，走 `/workflow-feedback-loop <task> --new`。

## 漏点地图：双字段 + severity（仅 pit）

每条 pit 记 `根因阶段`（归档到此文件的依据）+ `拦截阶段`（实际在哪抓），两轴攒成漏点地图供 archive 读。**加固优先级 = 频次 × 逃逸深度**（根因→拦截 隔得越远越贵）；逃逸深度只排序、**不进升级闸门**。severity 二元闭合：命中**数据丢失/安全/资金/不可逆**即 `high`，否则 `normal`——不做主观判断，高危坑踩一次已是事故。

## 条目格式：本 skill 是学习层格式的单一源

**教训优先**：一条踩坑真正要传下去的是**教训**——脱离这次具体场景也成立的本质经验（"接代理后先跑冒烟确认 click 通路"），不是这次事故的现场细节。`场景`/`修正` 降为辅助识别信息，只帮读者判断「这条是不是在说我遇到的情况」，不叙事、不铺垫。

**电报体**：`场景` / `修正` / `教训` / `启发` 只写结论，不写背景交代、不写过程叙述——像按字收费的电报，一句话说完。判断一句话是否合格：删掉它，读者是否失去可执行的信息？失去才留，没失去就是废话。

**踩坑条目**（写「踩坑」段；同主题已存在则次数 +1、追加场景/拦截阶段/出处，不新增条目）：

```
### [短标题]
- 教训：<一句话：这阶段该怎么做，脱离具体场景也成立>
- 场景：<一句话触发条件：什么输入/状态会撞上这条>
- 修正：<一句话：具体怎么改的，指向方案不复述过程>
- 次数：N
- 根因阶段：<...>     # 漏点地图根因轴
- 拦截阶段：<...>     # 漏点地图拦截轴
- 严重度：<high|normal>
- 出处：delivery/<task>, ...
```

**经验条目**（写「经验」段，阶段性启发，不计次数）：

```
### [短标题]
- 启发：<一句话：这阶段怎么做更好>
- 适用：<什么场景下用>
- 出处：...
```

## 写入逻辑

1. 读 `--file`，缺三段标题（`## 规约`/`## 经验`/`## 踩坑记录`）则补建空段。
2. 在目标段已有的 `### [标题]` 里按**语义相似度**（不只字面）找同主题：同根因/同类模式/仅措辞不同→同条目；主题接近但根因不同→新条目。**判断模糊时默认新增**——宁可后续手工合并，不错并淹没差异。
3. **pit 命中**：次数 +1，场景/拦截阶段/出处追加（`|` 分隔），severity 取更高者，教训与修正维持原样（有更精准的教训才改）。**pit 未命中**：按格式新增到「踩坑」段。**exp**：写「经验」段，命中则补充精炼，不计次数。
4. **升级检查**（条目未含 `[已升级]` 时）：pit 达**频次≥3 或 severity=high** → 升级；exp 达**信心/决定驱动**（AI 判断或人确认「该强制了」）→ 升级。动作：把该条目的**教训/启发**直接改写成一句 DO/DON'T 规约句追加「规约」段，原条目标题加 `[已升级]` 保留可追溯，提示用户 review 提炼是否到位。

## 边界

打印操作摘要（pit new / +1 / exp new / 升级）+ 文件 + 锚点。沉淀价值判断留给调用方——feedback-loop 闸值得性、手动 capture 由人确认、archive 出口人工确认兜底，本 skill 只管格式与写入。state.json 由调用方维护。双字段只服务 pit，经验不挂根因/拦截轴。重复调用会连续 +1，去重责任在调用方。写入范围限定 `docs/spec-rule/`。
