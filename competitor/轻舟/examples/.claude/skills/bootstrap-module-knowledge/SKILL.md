## 前置校验
用户未指定话题，拒绝执行

## 内容生成提示词
文档的意义？1.快速理解这个模块，让AI在没有打开代码前就大概能说出那句「I now have a clear picture of how this works」 2.为了用少篇幅的复合精炼知识，省掉运行时繁重的探索梳理工作。
值不值得写？价值 ≈ 复合度（凑齐要几次检索）× 命中频率 × 半衰期。
多写与少写？少写只是退回基线；多写却既稀释信号、又多一份会腐烂的内容。拿不准就不写，不为了文档而文档。
内容边界？只写事实，不做过于牵强的推断。
单文档规模？大文档的读取本身就有压力，复杂的模块要分而治之，沿独立子域/分支的自然缝拆成可按需加载的小块。预算不设上限，一定要把问题讲清楚。

review 时只凭文档、不凭刚看过的代码记忆，检查能否讲出模块怎么运转，以及内容是否符合本文的规范
文档生成完毕后，去project-overview.md维护一下索引。

## 和其他文档的边界

| 文档 | 职责 |
|------|------|
| **`module-knowledge/`** | **单业务模块的事实地图 + 本模块特有踩坑** |
| `tech-knowledge/` | 项目特有的横切机制（多模块共用） |
| `spec-rule/` | 团队级规范 + 跨模块阶段性踩坑 |
| `project-overview.md` | 始终加载的压缩包；服务级模块清单 |
