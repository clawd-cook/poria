# Relay 设计稿分析

> 目标：**圈定要实现的图层范围 + 解析每个图层的设计语义**，产出一张「图层 → 语义映射表」。
> Relay MCP 使用 → 见 `relay-mcp.md`。

## 一、产出（先锚目标，再谈流程）

**主产出 —— 图层语义映射表**（每行一个被圈定的状态帧）：

| 列 | 含义 | 硬要求 |
|---|---|---|
| nodeId | 取数坐标（下游 MCP 调用的唯一入口） | `\d+:\d+` 真实值，**禁占位** |
| 状态名/语义 | 这帧是什么状态/变体 | 读 `characters` 非 `name` |
| 分组 | 归属哪个组件（容器/条目/原子） | — |
| 置信度 | 高 / 中 / 兜底 | 决定下游是否二次核验 |

**附产出**：设计稿基准宽度（750/375）· 设计链接（含 fileKey）· 宿主帧（仅 iterative）· **待确认/缺口清单**（对不上 PRD 的差异、拿不到的帧、低置信项——显式列，不静默吞）。

**验收标准**：下游拿这张表，**不回看设计稿就能干活**。做不到 → 这张表没到位。

**边界（防膨胀）**：只解析「是什么」（圈定 + 语义），**不做「长什么样」**（px/字号/色值归下游 `relay-component-analysis` 展开代表帧时才拉）。**本阶段是目录 + 索引，不是正文。**

## 二、总则（token 纪律 + 隔离）

- 设计稿 metadata 通常 50k–200k 字符、截图占用大量 token → **禁止主 agent 直接处理，必须 subagent 隔离**（含勘察）。
- 探结构走 `get_design_metadata` 且 `maxDepth=1`；**别对 page/canvas 级容器调 `get_design_context`**（单次 200k+ token）。
- 一份设计稿只做一次完整解析（explore 阶段），后续通过落盘文件复用。
- 截图预算：全程 ≤ 5 张（勘察 ≤ 3 张）；能从 `characters` 读到状态名就别截。
- **无设计稿则跳过**（B 端常见）：用户未提供、PRD 也无内嵌链接 → 跳过本流程，TRD 帧映射章节写"无设计稿，基于 PRD 文字描述"，组件拆分改为纯 PRD 推导（不关联 nodeId）。

## 三、路径分流

拿到设计稿后，先按**用户有没有给种子**分两条路（全流程唯一的分叉点）：

| 路径 | 何时 | 范围 | 干什么 |
|---|---|---|---|
| **四、全页解析** | greenfield；或 iterative 但用户没给种子 | 整个新功能页/模块 | 勘察结构 → 从画布**找**出所有相关帧 |
| **五、模块解析** | iterative 且用户已给种子（代表帧 + 宿主，schema 拍2 必填门） | 用户种子圈定的模块域 | 以代表帧为**指纹 + 定位**，在其所在域内**发现模块其余变体**（有界，不扫全画布） |

两条路各自取到帧后，汇到 **六、收口（自检 + 输出）**。

> **subagent 隔离与确认闸**：
> - 全页解析信息未知 → 先勘察 → 回主 agent 定向确认 → 再取料（**两趟 subagent**，闸由 schema explore 段编排）。
> - 模块解析域由用户种子圈定 → **一趟直接取料**（域已知，无需全局勘察/确认闸）；仅当种子不足以定位域时才回退一次轻勘察。

## 四、全页解析（greenfield / 无种子）

> 从画布找出所有相关帧。核心：**先勘察结构、再自适应取料**，不预设设计稿长什么样。

### 勘察（画地形）

`get_design_metadata` `maxDepth=1` 探顶层，**只判结构、不下钻、不测量**：
- **定锚点**：有 `node_id` → 直接用为锚点；无 → 对 page 顶层 `maxDepth=1`，按优先级选主帧（① 名称含「视觉稿」的 Frame 取面积最大；② 无明确命名 → children 最多且尺寸最大的 Frame）。
- **拓扑**：多画板规整型 / 单根巨型白板型 / 混合。
- **交互稿甄别**：整份是线框/prototype（帧名含「交互稿/prototype/低保真」、无精确色值、灰阶线框）→ 停，回报「请提供视觉稿链接」；视觉稿中混有交互页 → 跳过交互页并标注。
- **版本歧义**：仅当撞见"锚点旁并排多块同构 board / 带方案·定稿标签" → 记入待确认（问用哪版，靠文字标签非几何）；不撞见不提。

### 分区（功能性，不靠层级）

把关注范围切成功能区：

| 区 | 特征 | 用途 |
|---|---|---|
| **陈列区**（状态库） | 同类 symbol 成排/成列 + 行列文字标注 | 变体最全，**完整性分母** |
| **整页 mockup** | 设备宽完整页面、模块作 instance 内嵌、含状态栏/导航 | **host 只从这取** |
| **散落帧** | 零星单独画的帧 | 补漏 |
| **噪音区** | 流程箭头 / 走查QA批注 / 切图资产 / 粘贴截图 | **显式圈出排除** |

> **区可能焊死、无独立容器**（陈列面板贴着整页 mockup）→ 别指望整容器抓，改按「**节点类型（instance/symbol） + 行列标注**」识别。

> 勘察 + 分区跑完，把候选锚点 + 分区 + 歧义汇成【待确认清单】返回主 agent；**定向确认后**再进「取料」。

### 取料（按需从区取，非遍历）

- **变体清单 ← 陈列区**：对 section 容器 `get_design_metadata` 枚举每个状态 symbol 的真实 nodeId。
- **host 帧 ← 整页 mockup**：host **只允许**从"页面内嵌 instance 的父页面"取（矩阵 symbol 的父是画布/白板、不是 host）。取模块 instance 的父页面，`get_screenshot` 确认同框（含新模块 + 相邻既有楼层）。
- **补漏 ← 散落帧**。
- **噪音（流程箭头等）**：「分区」已归噪音区排除，不入映射表。其编码的状态跳转关系属下游 TRD 行为设计，**本阶段不 formalize**（守"只索引不测量"边界）。

### 标语义（全阶梯推断）

每帧标 **状态名 / 分组 / 置信度**（与输出表一致，不多标角色/关系等无出口项）。

**状态名识别**（按优先级，读 `characters` 非 `name`）：

| 优先级 | 来源 | 容差/说明 | 置信度 |
|---|---|---|---|
| 1 | 帧自身 `name` 有明确语义 | 如"活动首页-可玩" | 高 |
| 2 | 相邻文本节点 | 帧旁 TEXT，y 差 ≤30px 且 x 在帧 ±50px，或正上方 -20~-80px | 高 |
| 3 | **矩阵行头/列头标注** | 行头（帧左侧同 y）/ 列头（帧上方同 x），容差按矩阵行距/列距放宽 | **中·需核验** |
| 4 | 帧内顶部 TEXT | 帧内第一个 TEXT 的 `characters` | 中 |
| 5 | 纯视觉、无任何标注 | `get_screenshot` 兜底 | 兜底 |

> `name` 常是"文字165"这类自动层名、还会过期（见过 `name="¥9190.00"` 而 `characters="¥3999"`）；`characters` 才是真实文案。优先级 2/3/4 直接读、别为读字截图。

**排序 + 噪音过滤**：按 y 分行（容差 ≤50px）、行内按 x 排序；排除名称含「判断流/引导线/连接线/条件判断/流程/大纲」及 w<50 或 h<50 的节点。**不按宽度区间筛帧**——离群宽度的状态帧（如超长空态）也留，宁多列待判、不静默漏帧。

**分组**：① 帧名 "-"/"_" 前公共前缀相同归一组；② 无前缀按 y 同行归一组；③ 仍难分按 PRD 场景。

> 设计稿基准宽度：取候选帧的主流宽度（如 375/750）；整页与模块内容宽并存时**两者都报**（如"整页 750 / 模块 686"）。

→ 汇到 **六、收口**。

## 五、模块解析（iterative · 用户种子圈定域）

> 用户给**种子**（代表帧 + 宿主），工具以种子为**指纹 + 定位**，在种子圈定的域内**尽力补出模块的其余变体**——替用户减少讲解。**但"能补多少"取决于种子落在什么域**（见下「枚举」三情形）：陈列区种子能便宜补齐、页面内嵌/散落种子基本补不动。**发现有界**：只在种子域内、绝不扫全画布；**补不动就问用户，不硬扫**。

### 锚定（确认种子 · 提指纹 · 判域）

- **确认种子**：逐个 `get_design_metadata` 确认用户给的代表帧存在、取 name/坐标/尺寸；不存在/对不上 → 回报主 agent，不臆造。
- **提指纹**：从代表帧抽模块特征（同名前缀 / DOM 骨架 / 尺寸档），供域内识别"同一模块的变体"。
- **判域**（决定下一步能不能枚举）：
  - 种子在**陈列区 / 矩阵 section** → 域 = 该 section（成排承载变体，**可枚举**）；
  - 种子是**页面内嵌 instance** → 域 = 该整页（本页通常只一个态，其余态在别页）；
  - 种子是**散落单帧** → 父是画布/白板（枚举必爆炸）。

### 枚举（域内尽力补齐，findability 取决于域）

按上一步的域类型分三种，**行为不同**：
- **陈列区 section 域** → `get_design_metadata` 枚举 section 兄弟、按指纹纳入同模块其余变体：**能便宜补齐**（理想情形）。
- **页面内嵌 instance 域** → 本页通常只一个态、域内拿不到其余 → **不跨页硬扫**（每页大、token 贵），把"其余态在别页"列给用户，问「其余状态帧 / 或陈列区在哪」。
- **散落 / 父是白板** → 枚举必爆炸 → **只确认种子这一个态**，其余交用户，**绝不扫白板**。

> 共同纪律：只纳同源（同名/同骨架），混进的他模块/装饰/噪音排除；**补不动 → 问用户、不硬扫**；找到多少、哪些没覆盖，都在「六·收口·自检」如实标。

### 定 host

host = 用户给的宿主帧（页面内嵌 instance 的父页面，含新模块 + 相邻既有楼层同框）。
- 已给 → 直接用。
- 漏给 → 取模块 instance 的父页面，`get_screenshot` 确认同框；仍定位不出 → 标「宿主帧缺失，须向用户索取」回主 agent。
- **不得用模块单帧顶替、不得凭感觉猜楼层顺序/间距**（踩坑：新楼层插反、楼层间贴死）。host 固定 `分组=宿主帧`。

### 标语义（代表帧采用 / 新发现走阶梯）

- **代表帧**：用户给种子时通常已带状态名/场景 → **直接采用**为状态名与分组，置信度「高」。
- **域内新发现的帧**：走「四、全页解析 · 标语义」的状态名阶梯（按阶梯定置信度、需核验）。

→ 汇到 **六、收口**。

## 六、收口（自检 + 输出）

### 自检（设计稿内部，不越界比 PRD）

本 subagent 只解析设计稿、通常不持有 PRD → **不做 × PRD 对账**（"PRD 场景 ↔ 设计帧"是主 agent 的活，见 schema explore「交叉校验」）。这里只做设计稿**内部**自检 + 把不确定的显式吐出来：
- **完整性自检**：全页解析——各区（尤其陈列区）是否枚举齐、有没有漏帧；模块解析——域内变体是否找齐，并把**「还有别区的变体吗」**列给主 agent 兜跨区漏。
- **存疑抽样**：陈列区是"审阅陈列"、不保证 == 真实页面 → 抽 1–2 关键态拿页面内嵌 instance 截图比、防过时。
- **如实报数**：找到多少变体就报多少（如"域内枚举出 10 个变体"）；**是否对得上 PRD 交主 agent 判**，本阶段不替 PRD 取舍。
- **低置信 / 缺口** → 进「待确认清单」，**绝不静默丢帧**。

### 输出（返回主 agent，不自行落盘）

> **× PRD 对账在主 agent**（explore「交叉校验」，它同时持有 PRD 与本表）。本 subagent 只保证"设计稿这边解析全、存疑标出"，不判 PRD 符合性。

1. **图层语义映射表**：

   ```markdown
   | 序号 | 状态名称 | nodeId | 分组 | 置信度 |
   |------|----------|--------|------|--------|
   | 1 | 活动首页-可玩 | 10:13287 | 活动首页 | 高 |
   | 2 | 活动首页-无体力 | 10:13288 | 活动首页 | 高 |
   | 3 | 主态整页(含新模块+相邻楼层) | 10:13300 | 宿主帧 | 高 |
   ```
   > 末行（`分组=宿主帧`）仅 iterative 有；greenfield 无此行。

2. **设计稿基准宽度**（主流宽度；整页/模块并存则双报）。
3. **宿主帧**（仅 iterative；未定位到 → 标「宿主帧缺失，须向用户索取」，主 agent 据此索取，不得跳过、不得用模块单帧顶替）。
4. **待确认/缺口清单**（低置信项、对账差异、版本歧义）。

**置信度消费规则**（下游 `relay-component-analysis` 展开代表帧前用）：
- **高**：直接展开，无需额外确认。
- **中**：展开时须对该帧截图确认识别是否正确。
- **兜底**：展开前返回主 agent，由主 agent 向用户确认该帧含义后再继续。
