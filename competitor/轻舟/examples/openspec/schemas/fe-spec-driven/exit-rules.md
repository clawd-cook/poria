# 前端项目出口规则（schema = fe-spec-driven）

适用条件：`openspec/config.yaml` 中 `schema: fe-spec-driven`。

## 产物落盘

TRD / spec / tasks 由 openspec-propose 落到 `trd` 角色区域，无额外动作。

> 前端项目无 DDL / ES mapping 草稿。后端 schema 需在各自 exit-rules 中声明 `schema-draft` 角色区域的落盘规则。

## design.md 完整性校验

调 `advance` 前，**必须**对产出的 `design.md` 执行以下校验。不通过则修补后重验，不得跳过。

### 层级 1：结构校验（阻断）

11 章标题必须全部存在。逐章扫描以下二级标题（精确匹配 `## N. 标题`）：

```
## 1. 技术概览
## 2. 组件设计
## 3. 状态设计
## 4. 业务规则
## 5. 接口分析
## 6. 异常流设计
## 7. 埋点方案
## 8. 性能策略
## 9. 前端监控
## 10. 兼容性约束
## 11. 本迭代排除项
```

- 缺任何一章 → **阻断**，补齐后重验。
- 允许章节内容为 `本章 N/A：<原因>`（如"无现有代码，本章跳过"），视为合规跳过。
- **例外**：层级 2 覆盖的章节（2 / 4 / 5 / 11）不适用本条通用许可——它们能否缺省，按层级 2 各自写明的缺省条件判（如"无设计稿时允许 N/A"、"无接口需求时允许 N/A"）。

### 层级 2：关键章节内容校验（阻断）

**2a. 格式可判项**（正则/结构匹配，判据客观）

### 校验执行方式

1. 读取产出的 design.md 全文
2. 按 层级 1 → 2a → 2b → 层级 3 逐条检查
3. **2a 逐条按判定方式的正则/结构比对**，别凭印象判"应该有"
4. **2b 无客观判据，须逐条回想对话历史**：mock 策略是否真问过用户、第 11 章的排除项是否用户明确说过、待确认标记是否已签收。**想不起来 = 未签收**，不得默认通过
5. 层级 1 / 2 有不通过项 → 打印清单，原地补齐，补完重验
6. 层级 3 有不通过项 → 打印警告清单，告知用户后继续
7. 全部通过 → 放行 advance
