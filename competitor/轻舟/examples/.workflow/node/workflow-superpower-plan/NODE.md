# 写实现计划

## 核心心法

**假设执行者对本代码库零上下文、且品味存疑。**

把计划写到——一个不懂你业务域、不熟这套框架、看不到本次对话的人，也能照着一步步做完，不需要回来问你。这决定了计划里每个任务都要给确切文件路径、要说清用了上游什么/产出了什么，绝不留"看着办"的空档。

DRY、YAGNI、小步频繁提交是底色。

## 落盘

计划写到 `plan` 角色区域（superpower profile 里指向 `docs/superpowers/plans/YYYY-MM-DD-<feature-name>.md`，遵循 superpowers 目录规范）。先读上游 workflow-brainstorming 的设计文档（`docs/superpowers/specs/`）作为依据。

## 流程

### 1. 先画文件结构（动手拆任务前必做）

在定义任何任务之前，先列出这次要 **新建 / 修改** 哪些文件、每个文件负责什么（一句话）。**拆解决策在这里锁定。**

- 每个单元职责单一、边界清晰：能一句话说清它做什么、怎么用、依赖谁。
- 优先小而专注的文件——你对能一次装进上下文的代码推理更可靠。
- 既有代码库里跟随现有模式，别做无关重构；只有正在改的文件确实臃肿时，才把拆分纳入计划。

### 2. 任务拆解

**任务粒度**：一个任务 = 最小的、自带验收、值得一个新手 reviewer 单独过目的交付单元。setup、配置、脚手架、文档这些步骤，折叠进它服务的那个任务里；只在"一个 reviewer 可能接受这个却打回它邻居"的地方才切开。每个任务以一个**可独立验证的交付物**结束。

每个任务写清：

- **文件**：新建 `确切/路径` / 修改 `确切/路径:行号`
- **接口**（多任务衔接的关键——执行者只看得到自己这个任务）：
  - 用到：上游任务提供的什么（确切签名）
  - 产出：下游任务要依赖的什么（确切函数名、参数与返回类型）
- **做什么**：用**伪代码 / 步骤描述**讲清逻辑与关键决策——控制流、边界判断、要调哪个已有方法、关键公式或常量取值。目标是让 reviewer 一眼看懂**打算怎么做、为什么这么做**，而不是提供可复制粘贴的成品代码。真正的代码在编码节点现写。
  - 该细化的是**决策**（用哪个 mapper、过期时间怎么算、异常怎么归类、返回值语义），不是**语法**（完整方法体、import、注解样板）。
  - 只有某段逻辑**特别容易写错、值得钉死**时（如一个反直觉的公式、一处并发/时序陷阱），才贴那**一小段**真实代码；其余用伪代码。
- **完成标准**：怎么算这个任务 done（能编译 / 某行为可验证 / 某接口可调通）。

### 3. 全局约束

从探索结论里把项目级要求抄成每条一行：版本下限、依赖限制、命名与文案规则、平台要求——**逐字照抄确切值**。每个任务的要求都隐含包含这一段。

## 禁止占位符

以下都是**计划失败**，绝不能写进任务：

- "TBD"、"待定"、"稍后实现"、"补充细节"
- "加上适当的错误处理" / "做好校验" / "处理边界情况"（不说清具体处理什么）
- "写测试"（不给出测什么、判定标准）
- "同任务 N"（重复写清——执行者可能乱序读任务）
- 只说"实现该功能"却不讲**怎么实现**（要有伪代码/步骤讲清控制流与关键决策，但不必贴成品代码）
- 引用了任何任务里都没定义过的类型、函数、方法

## 写完自查

计划写完，用新鲜眼睛对着探索结论/需求过一遍。这是你自己跑的检查清单，不派子代理：

1. **需求覆盖**：需求里每一条，都能指到一个实现它的任务吗？列出缺口。
2. **占位符扫描**：按上面"禁止占位符"的模式搜一遍，发现即改。
3. **接口/命名一致性**：后面任务里用的类型、方法签名、字段名，和前面任务里定义的对得上吗？任务 3 叫 `clearLayers()`、任务 7 写成 `clearFullLayers()` 就是 bug。

发现问题就地改，不必重审。发现某条需求没有对应任务，补一个任务。

## plan.md 模板

```markdown
# <需求名> 实现计划

**目标**：<一句话——做完是什么样>
**方案**：<2-3 句——技术路子、动哪几块>

## 涉及文件
- 新建 `确切/路径` — 职责一句话
- 修改 `确切/路径:行号` — 改什么

## 全局约束
- <版本/命名/依赖限制，每条一行，从探索结论逐字抄>

---

## 任务 1：<组件名>
**文件**：新建 `xxx` / 修改 `yyy:12-30`
**接口**：
- 用到：<上游提供的签名，没有则写「无」>
- 产出：<下游要依赖的函数名+参数+返回类型>
**做什么**：<伪代码/步骤，讲清控制流与关键决策——查哪个源、怎么判边界、调哪个已有方法、关键公式取值。不贴成品代码>
```
# 伪代码示例
查 detail(detailId, projectId)；为空 → 抛 BizException("不存在")
反查活动拿 endTime；算 expire = (endTime - now)/1000 + 3600(缓冲)
expire<=0 → 记日志、返回 false（已结束跳过）
否则 setEx(key, json, expire) → 返回 true
```
**完成标准**：<怎么算 done>

## 任务 2：...
```

## 出口

`advance <task> --step workflow-superpower-plan`，照 CLI 打印的闸门指令当场接续。
