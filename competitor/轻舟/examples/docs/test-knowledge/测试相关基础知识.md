自动化测试相关指南

1.本地环境和测试环境网络是互通的，所以8080端口也是可以直接访问的。但是预发不行，预发只有常规的80端口可以访问。
2.如果http服务直接能访问通，那直接发起http请求是最佳的，如果访问不通就只能借助lbcli的deeptest的能力了。
3.除了http之外很多内容，比如mysql，jimdb，es，日志等我们都无法直接查询，需要借助lbcli的能力。
4.lbcli是我们的王牌产品，建议主动多用。它既能 fetch 物料，也能验证副作用。
5.登录态的可以通过lbcli getssologin导出给脚本使用。如果是lbcli的命令，他本身就能解决cookie的问题。
6.证据是人工评审的命根子——每次与被测系统之外的交互都必须落进报告的证据块，**绝不在用例里裸 `subprocess.run(...)`**（裸调绕过 conftest 的渲染，报告里什么都不留）。HTTP 走 `http` fixture、命令行（lbcli 查 DB/缓存/ES/JSF/配置）走 `cmd` fixture、日志检索走 `grep_log` fixture（logbook 专用，只留 time+message 精简证据，别用 cmd 裸跑 logbook——它的 json 每条带 line/raw 等重列，落进报告是一大坨），这些都自动落证。
7.这是一条**通用原则、不是按数据源枚举**：遇到框架还没给过示例的未知源（某个 SDK、内部工具、新的查询方式），同样要留证据——调 `record_evidence(title, request=..., response=..., **meta)` 把出入参手动落下。宁可多留不可漏留，别因为「没见过对应示例」就退回静默直调。
