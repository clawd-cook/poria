# 测试物料获取指南

> 自动化测试（test-plan 决策 → test-cases 细化声明 → run-autotest 执行）跑起来需要的**物料**——token / base_url、前置数据、测试账号、租户隔离、第三方依赖态——怎么由 AI 自主备齐，哪些必须停下来跟人聊。**决策（要人确认的风险）前移到 test-plan，趁人还在场拍板；执行（机械获取）留 run-autotest。**
> 核心矛盾：**尽量不打扰用户**（AI 有仓库代码 + lbcli，能解决大部分），但**有风险的物料必须摊开聊**。下面用「自主三档」把这个度钉死。

## 物料是什么

端到端用例发 HTTP 打被测服务，跑通需要的前置统称物料：

- **前置数据**：被测场景依赖的已有数据（某状态的订单、某 SKU、某账号），任务隔离在 `tenant_id=test_<task>` / JIMDB key 前缀 `test:<task>:`。
- **依赖态**：第三方/下游服务的预置状态（库存、配置开关、消息）。

物料分两半：**「验收」**（run-autotest 出口闸已覆盖：`成片 skip = 物料没就位`）和**「获取」**（本文档补的那一半）。

> **跨任务复发的物料按域编目**在 `docs/test-knowledge/物料地图`（由 `bootstrap-material-map` 生成）：某域有哪些物料、各自作用、预判什么档、从哪起手。本指南定义**通用策略与度本身**（三档规则、opencli 定位、批量摊牌、台账格式）；物料地图是它在各域的落地编目，test-plan 决策物料时照图索骥（拿场景→物料 + 档位先验）。

## 来源金字塔（轻 → 重，能用轻的不用重的）

1. **仓库代码（词汇，免费）**：接口契约、字段名、枚举字面量、错误码。test-cases 已在做的「只取词汇不取映射」。
2. **隔离域内自造（绿）**：在 `test_<task>` 租户/前缀内自己拼 payload、造/清数据。AI 的沙盒，随便造。
3. **lbcli（HTTP 之外一切的抓手，多用）**：领测试 token、查/造真实数据、查 DB/JIMDB/ES/JSF/日志/配置。**唯一能碰真实系统与非 HTTP 基建的臂，分档主要卡在它身上**（见下）。能用它自助的就别打扰用户。
4. **人（红档兜底）**：命中红线的物料，AI 备好上下文、批量列出、由人确认或提供。

## 批量摊牌

红/黄物料**不要 per-material 打断用户**——那会把「不打扰用户」直接打穿。

**时机：主摊牌在 test-plan，不在 run-autotest。** 物料风险是**场景的属性**（碰不碰真钱/真人/写操作，看 plan 场景就能判），不必等代码。决策摊牌前移到 test-plan——那时人正审 plan、还在场；拖到 run-autotest（尾段）人早切出去了。run-autotest 只对「看了代码才冒出来的新物料」做**残留摊牌**，正常路径应为零。

摊牌四步（test-plan 主摊牌 / run-autotest 残留摊牌同此式）：

1. 黄/红档物料起草成台账行（写清来源、档位、opencli 环境参数、为什么有风险）。
2. **一次性**列给用户：「这 N 个物料有风险，原因如下，请确认或提供」，逐条确认完才放行。
3. 用户确认后，台账对应行标记确认人/时间。
4. 绿档无需摊牌：test-plan 判定为绿即静默，**真正备齐在 run-autotest 执行**（test-plan 不本地跑、不造数）。**但「无需摊牌」≠「无需定规格」**——绿档物料的来源 + 确切参数 / opencli 命令原文（含环境）仍必须在 test-plan 填死到 run-autotest 能无人机械执行。档位只管「风险 / 要不要问人」，不管「规格全不全」；读场景「理论绿、没风险」也照样要把请求参数问清定死，否则漏到 run-autotest 会卡壳（那时人已切出）。

## materials.md 台账格式

落 `delivery/<task>/test/materials.md`。一行一物料，绿档静默填表、黄/红档高亮：

```markdown
# 测试物料台账 — <task>

> test-plan 决策（标档 + 🔴/🟡 摊牌确认，plan 粒度）→ test-cases 细化（落 case 粒度 + 确切 spec，继承档位）→ run-autotest 执行（获取并标状态）。
> 写物料的「目标环境」须 = .workflow/config.json test_env.target。

| 物料 | 用途(case/plan) | 来源 | 档 | 获取方式（opencli 含环境参数原文） | 状态 |
|---|---|---|---|---|---|
| 已支付态订单 ORD-1 | case-3 / plan-2 | opencli 写 | 🟡 | `lbcli order.create --env=test ...` | 已备齐 |
| 商品 SKU-001 存在性 | case-1 / plan-1 | opencli 读 | 🟢 | `lbcli sku.get SKU-001`（读，任意环境） | 已备齐 |
| 自造下单 payload | case-1 | 隔离域自造 | 🟢 | `tenant_id=test_<task>` 内拼装 | 已备齐 |
| 真实风控账号 | case-5 | 人 | 🔴 | 触发真实风控/PII，待用户提供 | ⏳ 待确认 |

## 待摊牌（黄/红，需人工 review）

- 🔴 真实风控账号（case-5）：会命中真实用户 PII，AI 不自造 → 请提供或确认改用合成账号。
- 🟡 已支付态订单（case-3）：opencli 写到 test 环境，已钉 `--env=test`，请确认环境无误。
```
